## 2. 资料: 真搜 (per 你 explicit ask)

### 2.1 Software testing industry standard

**ATDD (Acceptance Test-Driven Development)**:
- 先由 customer/team 定义 acceptance criteria
- 然后写 acceptance tests
- 然后开发 code 直到 tests pass
- 关键 = "tests define code behavior" = 验收标准先于实现

**3 Amigos Sessions**:
- Developers + testers + product owners 共同定义 acceptance criteria
- 在 implementation 开始之前
- 防止 miscommunication + 确保满足业务需求

### 2.2 LLM agent planning 文献

**Andrew Ng on Planning**:
- Planning = LLM 自主决定 steps to execute
- "Planning abilities will improve quickly" (LLM 还在演化)
- "Planning is less mature technology ... hard to predict what it will do"
- = 我 (LLM agent) 现在的 planning 能力不完美, 这是 systemic, not blame

**Pre-Act: Multi-Step Planning and Reasoning**:
- Planning BEFORE acting
- 多次 reasoning steps → 提高 LLM agent 表现
- = 我应该 explicit plan, 不 = 隐性 reactive

**Natural Plan benchmark (Google DeepMind)**:
- 测试 LLM 在真实场景的 planning 能力
- 最佳模型 < 50% accuracy
- trip planning (10 cities) < 5% accuracy
- = LLM 真不擅长 long-horizon planning

**Chain-of-Thought (Wei et al. 2022)**:
- Plan out reasoning path → better outcomes
- 即使在 LLM 内部, planning out reasoning 改善结果
- = 我应该 explicit think step-by-step, 不 = jump to action

## 5. ATDD 4-phase protocol (real ship)

```
Phase 1: ACCEPTANCE CRITERIA (定义)
  - 由你来 (用户) 或 共同 (user + agent) 定义
  - 写到 project layer (persistent)
  - 不可在 Phase 2+ 修改

Phase 2: PLAN (规划)
  - 基于 acceptance criteria 规划修改
  - 写到 project layer (PLAN_<DATE>.md)
  - 包含: goal, acceptance, trade-offs, pre-judgment

Phase 3: SHIP (实施)
  - 按 plan 实施
  - commit messages 引用 plan
  - 不可修改 acceptance criteria

Phase 4: VERIFY (验收)
  - 跑 acceptance tools
  - compare vs acceptance criteria
  - PASS / FAIL / DEFERRED
```
